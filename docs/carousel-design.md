# Carousel design decisions

Brief: user screenshots and instructions, updated 24 October 2026. These sources support patterns and constraints; they do not prove that this launcher is usable or WCAG conformant. Independent review of earlier snapshots is in `carousel-review.md`.

| Interface choice | Evidence or explicit requirement |
| --- | --- |
| Dominant landscape game-art hero, with a peek of adjacent art | Updated user requirement, referencing Netflix above the fold. Netflix's own [homepage guide and interface images](https://www.netflix.com/tudum/articles/netflix-new-homepage-layout-user-guide) and [product announcement](https://about.netflix.com/en/news/unveiling-our-innovative-new-tv-experience) provide the visual reference. The larger card proportions are our interpretation, not Netflix-prescribed measurements or proof of better usability. [Google's carousel documentation](https://developer.android.com/develop/ui/compose/components/carousel) describes visual collections and uncontained items. |
| Remove Home search, promotional headings, count, and separate hero | User's specific removals. Library retains search and a stable collection. [Nielsen's minimalist-design heuristic](https://www.nngroup.com/articles/ten-usability-heuristics/) supports excluding irrelevant or rarely needed content; it does not establish which controls this particular user needs. |
| Countdown runs by default; game hover pauses and leaving resumes | Explicit 24 October user instruction removes pause/start and persistent focus/manual stops. Old saved pause preferences are ignored. Hovering the game viewport freezes elapsed time; hovering navigation dots does not. This differs from the rotation controls and focus-stop behavior recommended by [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/); it is a user-directed variant, not a claim of APG conformance. |
| Dot selectors instead of visible previous/next arrows | Explicit updated user requirement. APG distinguishes selection controls from rotation control. Our named native-button group uses one roving dot stop, Left/Right and Home/End; these provide adjacent and direct navigation without a hundred Tab stops. This is a tested implementation choice, not a claim that APG prescribes this exact variant. |
| Named carousel/slide groups, roving cover stop, deliberate announcements | [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) supplies semantic and announcement guidance. Automatic changes do not repeatedly announce titles. The extra roving cover stop is our keyboard-entry choice. No cloned covers or invented tab/listbox semantics. |
| Game title, Play/details and music in a hover/focus overlay | User requirement. [WCAG hover/focus guidance](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) supplies persistence, keyboard equivalence, pointer travel, and Escape dismissal constraints. Touch uses selection to reveal controls. |
| A dark gradient behind overlay text, no frosted cover tray | User requests removing the tray. Contrast backing follows [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). [Fluent materials](https://fluent2.microsoft.design/material) distinguishes transient acrylic from other surfaces. This gradient is neither native Acrylic nor modal Smoke. |
| Blurred wallpaper and static volumetric light behind sharp covers | Explicit user artistic direction. Blur radius, glow intensity, tint and beam shape are implementation choices, not researched usability findings. Decoration has no input or accessibility role. |
| Thirty-second dwell with an active-dot countdown ring | Explicit user timing/progress requirement. The named selector remains a button; its ring and seconds share the advance clock. Non-live timer text gives remaining time. Hover, dialogs, hidden windows and launch suspend the clock. Passive refreshes, pending-to-installed migration and route round trips preserve elapsed time; deliberate selection resets it. Focus alone does not stop it; automatic advances retain corresponding control/dot focus. One game has no next-slide countdown. |
| Smooth adjacent hero transitions | User's smooth-motion requirement. [Fluent motion](https://fluent2.microsoft.design/motion) recommends purposeful transitions and distinguishes easing. The 420 ms transition is an implementation choice, not a Netflix or Fluent prescription. Nonadjacent selection skips a long fly-through; reduced motion changes immediately. |
| Pause while hidden, during a dialog, or during launch | Engineering constraints that prevent unwanted changes during another task. [WCAG Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) requires user control over qualifying ongoing movement. |
| Reduced motion removes transitions while the countdown remains enabled | Latest user instruction keeps countdown enabled by default. Slide changes are immediate under reduced motion. [WCAG interaction-animation guidance](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) supports suppressing transition motion; automatic operation here follows the user's specific direction. Jungle stops moving; launch artwork stays static. |
| Music crossfades on game selection and continues across routes | Explicit user requests. The same audio instance and gain continue through Home/Library/Catalogue; route changes do not stop, replay or fade it. Music controls move to a compact header mute button outside Home. Game changes still use 600 ms cosine-eased fades. Wheel pause remains silent through navigation/automatic cycling; explicit music Play or non-wheel selection can resume, respecting saved mute/level. [WCAG audio control](https://www.w3.org/WAI/WCAG22/Understanding/audio-control.html) supports retaining playback control. |
| Background treatment is shared by every route | Explicit continuity requirement. Wallpaper/jungle elements remain mounted, with identical blur, opacity, scale and vignette styles. Navigation preserves the selected game's art and jungle playback; only meaningful game/theme selections change it. |
| Wheel navigation snaps through games | Explicit user request. Pixel/line/page input is normalized. A 24-pixel threshold and 420 ms small-input throttle are implementation heuristics. Large events queue adjacent transitions, bounded to four pending steps. Raw deltas do not establish exact hardware detent counts. Scrolling pauses music at boundaries, in one-game collections, and within enlarged text. Overflowing text scrolls before changing games. Ctrl-wheel keeps zoom behavior. |
| Pending installations in Home and Catalogue, with game actions disabled | Explicit user request replaces the Downloads page. Namespaced pending IDs carry no executable/launcher route. Transfer completion does not enable Play; verified library discovery replaces the pending entry. Catalogue keeps transfer pause/resume/cancel/retry and archive import separate from game launch/open actions. Native progress is indeterminate for unknown totals. Phase announcements avoid byte-by-byte updates, following [WCAG status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). |
| Bold open orbital logo and satellite | Explicit user artistic request. SVG-native artwork replaces the thin planet drawing across header, tile/favicon, PNG/ICO, executable and shortcut. Shape, weight and color are artistic choices, not usability findings. |
| Small drawn dots within 28 x 32 px targets, visible focus outlines | [WCAG target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) concerns hit area, not the drawn circle. [Non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) supports distinguishable control/state boundaries. Current dots differ in size as well as opacity. |
| Keep launchers, navigation, library search, Catalogue, Settings and title-bar controls | Existing authorized functions. The Downloads page and header button are removed at the user's request. [Electron title-bar interactions](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions) explain why interactive controls must remain outside drag regions. |

Landscape art stays sharp. Portrait-only and square package art is contained within the hero rather than stretched or cropped to imitate a missing landscape image. Missing art uses a named fallback; Library's existing artwork setup remains available. Image availability is not evidence of image quality or completeness.

No added promotional copy, decorative captions, unverified social proof, reflection floor, animated particle field, fake depth controls, or duplicate search bar is part of this design. The requested lighting is static. Final acceptance records implementation checks separately from source rationale; it is not a screen-reader or user-study certification.

Catalogue transfer details use a closed native disclosure, leaving posters directly beneath the filters. The user requested less intrusion; historical warnings stay in this disclosure while active downloads use ordinary poster cards. Recovery controls and archive import remain available on demand. [HTML disclosure semantics](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element) explicitly support additional information and controls behind a summary. Compact status overlays omit long recovery instructions, which remain in the disclosure.

24 October follow-up: Catalogue uses ten equal columns with the existing 2:3 poster aspect ratio, per user direction. Launch artwork expands from the selected card to the viewport, retains its proportions with contain, and fades after the launch handoff (minimum 2.2 seconds). Launch IPC starts immediately in parallel; process spawn or launcher handoff does not prove that the actual game is ready. Errors dismiss promptly, missing art uses the title, and reduced motion uses static art. The existing launch-animation preference is retained for compatibility. This replaces the previously requested vortex. Native window controls occupy a quiet 32px strip, with the Catalogue modal below it. [Electron custom title bars](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar) document overlay height/color and safe-area support; the exact sizing is our response to the user screenshot.

24 October collection update: Library and Catalogue now share one route called Library. Installed posters come first on the first catalogue page, with Play and options; available games use Install to open their PlayZip page. Installed, Favorites and Recent views work without the remote catalogue. Launch artwork now uses cover to fill the viewport, with a 1.6-second expansion and a 4.8-second minimum display before fade. Reduced-motion and launch-error behavior stay the same. The transfer menu can delete staged downloads; game options uninstall local folders through the Recycle Bin or open the registered platform uninstall flow.
